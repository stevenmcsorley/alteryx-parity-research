# Inputs needed — what can and cannot be fetched autonomously

## Public material already identified

- Official Designer Tools List (323 category entries manually transcribed, XML identifiers manually transcribed, to cross-check on a connected machine).
- Reference 2026.1 release notes and dated patch build.
- File extension glossary and public descriptions of workflow serialization, macros and packaged workflows.
- Sample workflow documentation, AMP/original engine reference and role/add-on differences.
- REA source, documentation and installation requirements.

## Operator-provided material (not contained here)

1. **Valid Alteryx entitlement** and a legitimate copy of the exact reference build. Download/activate through the official Alteryx One application; do not upload installers or private binaries to GitHub.
2. **Approved legal scope** before REA binary inspection or behavioural studies restricted by applicable contracts. Decide permitted methods with qualified advice if required.
3. **Sample workflow corpus** generated by the entitled operator and permitted for our use. Installed examples are referenced in Designer via Help > Sample Workflows > Learn One Tool at a Time; check their licence before redistribution.
4. **Reference-run results** produced using approved test data and an authorised application. Capture input hashes, config/engine version, output hashes, exact errors/warnings and execution properties.
5. **Separately licensed packs** for predictive tools, geocoding/demographic packages, Intelligence Suite, vendor SaaS add-ons or other tools. Capture only permissioned test scenarios.
6. **Test credentials** for third-party connectors; store in OS secret storage, never in repo, logs, workflows or screenshots. Use sandbox accounts with minimum permissions.
7. **External SDK/driver environment** for database connectors, R/Python scripting and application packaging; record driver/library versions and licensing constraints.

## Safe local reconnaissance (metadata only)

After an authorised reference install, `scripts/inventory_local_reference.ps1` can write an **untracked local** file listing allowed file paths, sizes, selected metadata and hashes. It does not collect source code, reverse-engineer binaries, copy executables, attempt to activate licences or bypass controls. Treat even paths as sensitive if they identify the owner or organisation.

## Freshness caveat

`/current/` is not a fixed 2026.1 snapshot. Tool names, role policies and XML names may have changed. The baseline report must include source retrieval UTC timestamp and page SHA256. Compare the retrieved list against the pinned 2026.1 installation and record differences as build-specific, not assumed errors.
