# Performance measurements

Generated by `python scripts/benchmark.py --rows 200000`. Engine 0.1.0, Python 3.12.5, Windows 11, Intel64 Family 6 Model 183 Stepping 1, GenuineIntel.

Timings are wall-clock on one machine and vary between runs; they are measurements, not guarantees. Peak memory is the Python-allocated peak (tracemalloc), excluding interpreter baseline.

## Parallel branches and spilling (one input, seven independent tools, each followed by Count Records)

| Configuration | Seconds | Peak MB | Spills |
|---|---:|---:|---:|
| 1 worker | 41.72 | 123 | 0 |
| 4 workers | 42.40 | 145 | 0 |
| 1 worker, 20 MB memory budget (spilling) | 53.28 | 146 | 13 |

Notes: kernels are pure Python (ADR-001), so CPU-bound branches gain little from threads (GIL); streaming bounds memory for eligible linear segments; the memory budget spills idle intermediate tables to disk, which bounds memory when many large tables coexist; in this benchmark the peak is set by the single largest operation (one kernel plus its inputs), so spilling adds time and reload overhead without lowering the peak. Kernel-level external algorithms (external sort/aggregate) are required to bound that and are not implemented yet. Arrow-backed kernels are the planned optimisation path and must pass the same conformance cases.
