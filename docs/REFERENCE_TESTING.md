# Test-oracle design and accuracy acceptance

## Test levels

1. **Schema:** column names, types, order, metadata, nullability, input/output anchors.
2. **Scalar semantics:** coercions, separators, Unicode, null/empty, float edge cases, regex features, locale and date/timezone.
3. **Relational correctness:** sort order, grouping order, duplicate joins, missing keys, pivot/unpivot, row IDs, case sensitivity, deterministic sampling.
4. **Statistical fidelity:** estimation procedures, convergence, confidence intervals, choices of default algorithms, random seeds, tolerances with mathematical justification.
5. **Visual/reporting fidelity:** document output correctness, font metrics, layout, chart scales, map CRS and legend semantics; own design assets.
6. **Workflow compatibility:** import, nested macro execution, app parameter binding, serialisation, package dependencies, repeated runs and cancellation.
7. **Connectors:** OAuth and credential scopes, pagination, retries, rate limits, schema evolution, restricted permissions, failure and refresh behaviour. Use permitted sandbox services.
8. **Operational:** p50/p95, scale, memory, spill, crash recovery, inaccessible source failure, reproducibility.

## Core oracle contract

For each tool, create cases with: `case_id`, `tool_id`, `target_build`, `original_engine`, `config_digest`, `input_digest`, `expected_digest_or_metrics`, `comparison_rule`, `reference_provenance`, `licence_status`, `test_status`, `reviewer`, and `timestamp_utc`.

Comparison rules: `exact` for integer/string/schema, `numeric-absolute-relative` with explicitly recorded thresholds, `unordered-multiset` where order is contractually irrelevant, `statistics` only for stochastic methods, `artifact-diff` for spatial/report formats, and `error-contract` for anticipated failures.

Do **not** alter comparators to make failing implementations pass. An unexpected failure is a research task. Example code/fixtures in this repository are independently generated and not assertions about the vendor's output.

## Minimum conformance per configuration

Normal-case data; empty inputs; nulls; duplicate keys; Unicode/large strings; numeric precision/overflow; signed and unsigned; dates/DST; variable fields/schema drift; malformed files; resource limits; engine-order compatibility; API errors; user cancellation; path/sandbox errors; injection and secret-exfiltration negative cases.
