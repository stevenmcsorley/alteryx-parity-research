# Executable development plan: no catalogue scope cuts

This is a dependency schedule, **not** a trimmed feature set. All 323 entries remain in the matrix from the beginning. The goal is original full-function replacement, not copied code/assets.

## Stage A — source and rights evidence

- Version-lock installed build 2026.1.4.126. Record SHA256 of approved, locally-held binaries without sharing them.
- Run public help catalogue synchronization. Compare source diff with `data/tool-list-seed.txt` and stage a checked update.
- Document exact application entitlements and permitted study methods. Without permission, stay with public specifications and independent fixtures.
- Record how to access one-tool examples and whether example data can be retained.
- Produce a dependency graph: tool -> required runtime/connector -> external service/data -> permission -> evidence.

**Gate:** 100% inventory accounted for; research gaps visible, no made-up parameters or docs links.

## Stage B — general engine/editor

- Arrow-like typed batches, explicit nulls, variable schemas, spill and cancellation.
- DAG validator, ports/anchor cardinality, caching, lineage and reproducible execution.
- Plugin descriptors and versioned per-tool configuration schemas.
- Original desktop editor (React/TypeScript), tool palette, property panel, results browser, keyboard and accessibility contracts.
- Original workflow format; separate read-only importers for permitted legacy formats.
- Security: OS secret vault, scoped integrations, sandboxed untrusted scripts, auditable network/data transfers.

**Gate:** real CSV -> filter -> join -> group -> CSV with schema/null/error tests and observable execution. The `engine/independent_engine` Python testbed supplies only a limited technical foundation, not production semantics or vendor parity.

## Stage C — exhaust catalogue in dependency order

1. In/Out, Preparation, Join, Parse, Transform, Documentation.
2. Developer, Interface, macro/app runtime, dynamic tools, In-Database, multi-engine behaviour.
3. Reporting, connectors, databases, data types, data packages, Address, Demographic, Calgary, Spatial.
4. Data Investigation, Predictive, AB Testing, Time Series, Predictive Grouping, Prescriptive.
5. Machine Learning, Text Mining, Computer Vision, AI Tools and optional/deprecated/SDK tool categories.

**For every tool:** identity; sources; inputs/outputs; config/defaults; types; errors; side effects; real implementation; unit/property/integration/security tests; performance; reference comparison when authorised; review. Record unresolved unknowns rather than guess.

## Stage D — end-to-end compatibility and release

- Round-trip and execute representative `.yxmd/.yxmc/.yxwz/.yxzp` workflows with true dependencies and realistic data.
- Full cross-tool suite, version-aware behaviours, user-supplied sandbox connectors, scientific reproducibility and numeric tolerances.
- Signed desktop bundles, upgrades, telemetry choices, SBOM, penetration review and real customer testing.

**Gate:** never describe the system as 100% compatible while any tool is unimplemented or blocked. State separately catalogued / specified / implemented / vendor-reference-verified numbers.

## Realistic planning note

A full commercial-grade reimplementation across 29 tool categories is a substantial multi-year engineering undertaking for a small team, not a task REA can automate in one pass. Prototype times should never be treated as full-parity estimates. Some integration- or data-dependent behaviours may be inherently non-equivalent without separately negotiated rights.
