# Programme: full feature parity without a fake MVP

**Principle:** All 323 category entries are in scope from the first day. Stages express dependencies and validation order, not acceptance of a permanently reduced scope.

## 0. Verified source and entitlement baseline

Pin product/version, permitted access, list of installed add-ons and representative real files. Enrich catalogue with XML IDs and per-tool public help links. Record external providers and deprecations. Approve responsible reverse engineering boundaries.

## 1. Core runtime and editor

Own workflow schema; config-schema parser; DAG validator; typed tabular batches; execution graph scheduler; results inspector; formula expression engine; UI graph with undo/redo and multiport connections; packaged plugin contracts; importer architecture. Deliver fully passing internal tests before claiming tool parity.

## 2. Foundational deterministic tools

In/Out, Preparation, Join, Parse, Transform, Documentation, Developer support. Exact schema and row-order semantics and exhaustive edge-case tests. This unlocks most compositional test workflows.

## 3. Macros, apps, file compatibility and integrations

Interface/analytic apps, batch/iterative macros, nested workflows, roundtrip import, code tools and SDK, In-DB query compilation, 3rd-party connectors. Dependency matrix includes permissioned service environments.

## 4. Advanced engine suites

Reporting/rendering, geospatial, Address, demographic data packages, Calgary, deprecated/legacy behaviour, statistical Data Investigation, Predictive, Time Series, AB, Predictive Grouping, Prescriptive.

## 5. Intelligence suites

Machine Learning, Text Mining, Computer Vision, AI Tools, model connectivity, local inference and secure enterprise provider adapters. Build with independently verifiable, reproducible algorithms and documented data rights.

## 6. Parity campaign

Pin an evolving matrix of tool name + XML identity + versions + configurations + test/evidence statuses; produce automated release reports by category and compatibility axis. Build cross-tool workflow suites. Differential-test permitted reference cases; never fabricate oracle outcomes.

## 7. Shipping and commercial readiness

Signed installer, self-update, secrets vault, telemetry opt-in, audit, accessibility, documentation, SDK and migration, benchmarks, security assessment, commercial licensing review, scalability targets, user trials and support.

## Review gates

- Source completeness: catalogued identity, docs and dependencies accounted for across all categories.
- Semantic completeness: contract for every tool, even if implementation blocked.
- Implemented: real tool code, real inputs/outputs, supported errors.
- Verified: evidence-backed tests passed; external systems validated in authorised environments.
- Release: user-visible availability, capability exceptions and unsupported adapters disclosed.

## Significant blockers that cannot be solved by REA alone

Paid datasets, private SaaS APIs, proprietary external algorithms, vendor licensing, unsupported platforms, hardware resources, nondeterminism, compatibility across versions, privacy and secure credential handling.
